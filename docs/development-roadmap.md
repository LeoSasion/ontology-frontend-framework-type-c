# AIBI-C 开发顺序

## 先记住一条主流程

用户不需要先学会建模。产品只要求用户沿着这一条路径前进：

`导入真实数据 -> 生成证据摘要 -> 描述一个图表 -> 核对证据 -> 确认写入`

每一步都有唯一承接页面。其他页面只提供摘要和跳转，不复制完整操作。

## 当前状态

| 事情 | 现在的状态 | 用户实际看到的结果 |
| --- | --- | --- |
| 没有数据时开始 | 已完成 | 所有入口都引导去数据源，不显示样例图表、样例答案或假数据。 |
| 从真实数据生成单图 | 已完成 | 默认一次对话只起草一个图表；字段不清楚时最多追问一次。 |
| 证据和写入边界 | 已完成 | 来源、口径和回执先展示；真实写入只在草案确认后发生。 |
| 刷新后继续上次流程 | 已完成 | 待确认草案回到 AI；已有证据但没有图表回到仪表盘；未画像的数据回到数据源。 |
| 多种真实数据验证 | 进行中 | 需要用不同结构的数据验证系统没有依赖某个行业字段名。 |
| 带证据导出 | 未开始 | 单图主流程稳定后再做结果导出。 |
| 整套行业看板 | Beta | 只做预演和确认，缺字段的组件必须省略并说明原因。 |

## 接下来严格按顺序

### 1. 先证明通用

用至少两个不同业务领域、结构不同的数据集，分别验证：

`导入 -> 证据摘要 -> 单图 -> 证据 -> 确认`

这一步不把数据写进代码，也不把数据提交到仓库。验证使用临时工作区，结束后恢复原工作区。

### 2. 再修新手路径

只修真实流程中出现的阻力：

- 首页只显示当前最必要的一步，其余能力收在结构清晰的折叠区。
- 页面跳转携带当前工作区、数据表、看板和证据上下文。
- 不确定字段、关系或结果不默认展示为确定结论。
- 同一个写入动作只保留一个完整确认面。
- 横屏、竖屏和正方形 PC 比例下，文字和控件都不能被挤压、裁切或重叠。

### 3. 最后扩大交付范围

单图闭环稳定并经过真实数据验证后，再做：

- 导出结果、来源、口径、查询时间和缺口。
- 本地升级、恢复和回滚的交付流程。
- 多行业验证后，再评估是否把整套看板 Beta 升级为稳定能力。

## 明确暂时不做

- 云端账号、多人协作、远程托管和隐藏遥测。
- 预置行业样例、默认业务结论或假数据。
- 把高级字段、关系、公式和布局工具默认展开。
- 因为某个客户数据能跑通，就把行业字段写成产品默认值。

## 每轮完成标准

每轮代码改动都必须同时满足：

1. `npm run build` 通过。
2. `npm run verify`、`npm run verify:ai-reliability` 和 `npm run verify:workspace-flow` 通过。
3. 相关 UI 闭环在空工作区和真实导入工作区都通过。
4. 文档只保留当前事实，不复制过期的测试结果或旧产品名称。
