# AIBI-C 产品体验标准

本文件定义用户可观察的交互边界；组件结构和视觉细节以代码为准，验收场景见 [产品验收矩阵](product-acceptance-matrix.md)。

## 首次成功流程

默认流程是：`接入数据 -> 生成证据 -> 描述问题 -> 核对结果 -> 确认写入`。

- 空工作区只显示一个主任务：接入真实数据。
- 有数据但无当前证据时，主任务是生成证据摘要。
- 有证据时，主任务是描述问题或图表。
- 有待确认草案时，主任务是核对影响并确认或拒绝。
- 高级建模、关系、公式、布局、Provider 和技术回执默认收起。

## 页面职责

| 页面 | 主职责 | 不应承担 |
| --- | --- | --- |
| 工作区 | 当前任务、可信分析旅程和最近结果 | 重复完整对象管理器 |
| 数据 | 接入、预检、字段、质量、语义和关系 | 隐式生成业务结论 |
| 分析 | 问题、澄清、结果、证据和草案确认 | 直接执行未确认写入 |
| 看板 | 已保存图表、布局和高级编辑 | 为新工作区注入默认组件 |
| 证据 | Run、Receipt、Unit、Job 和导出记录 | 把历史证据冒充当前结果 |
| 设置 | 工作区、语义审核收件箱、Pack、Connector、Provider、迁移和配置 | 占据新手默认路径，或让用户纠正绕过提案与复核 |

## 对象归属与路由

- 每个对象只在一个所属页面完整展示；其他页面使用链接、摘要或状态提示。
- URL 保存真实对象上下文：`table`、`view`、`dashboard`、`run`、`action`。
- 切换页面时只保留该页面支持的上下文；刷新、前进和后退必须可恢复。
- 对象不存在或已删除时显示空态和恢复入口，不静默选择另一个对象。
- 完成导入、创建或确认后打开实际生成的对象，不把结果隐藏在全局浮层。

## 渐进展示

- 首屏只保留一个主操作，次要操作不与主操作争夺视觉优先级。
- 用户需要时再展开字段、筛选、关系、公式、样式、布局和技术证据。
- 阻塞信息靠近对应操作，说明原因、影响和可执行的下一步。
- 不以占位样例、假数字或默认业务问题解释空态。
- 响应式布局可以折叠次要说明，但不能隐藏工作区切换、主导航、高级工具或设置入口。

## 确认与删除

- 只读、解释、预览和 dry-run 不要求确认。
- 一次真实写入只有一个确认面；预检已经展示影响时不得再增加重复预演。
- 确认面必须展示目标工作区、对象、影响、依赖、来源指纹和可恢复性。
- 删除来源或对象前列出引用者与连带影响；拒绝不改变状态，确认后返回回执。
- 覆盖、Pack 启停、Connector 同步、Job 取消、恢复和迁移遵循同一模式。

## 图表与看板

- 默认图表请求只生成一个最小草案，先证明口径，再提供高级编辑。
- 创建空看板只创建看板容器，不自动添加组件。
- 无兼容数据形状、关系不安全或证据过期时明确阻断，不渲染误导性空图或零值。
- 连续分析在当前结果的高级比较区建立或扩展探索线程；结果板只显示血缘、业务摘要和实时状态，不复制结果表，也不另造一个全局工作流。
- 线程、锚点和板项写入使用就地预演与一次确认；窄屏按血缘纵向排列，所有操作均可用键盘完成。
- Beta 领域方案只在对应 Pack 已启用且字段证据满足时出现，并披露命中与省略单元。

## 可访问性与文案

- 键盘可到达主要操作、导航、对话框和展开控件；焦点状态清晰。
- 表单有可见标签，错误不能只依赖颜色，状态文案同时说明结果和下一步。
- 使用面向业务用户的名称；技术标识只在详情或证据层出现。
- 中英文界面表达同一行为，不在生产文案中保留测试占位符。
