# AIBI-C Product Requirements

`PRODUCT.md` 定义产品定位和边界；本文件只维护当前用户需求、功能要求和发布条件。

## User Problem

业务用户拥有本地表格或 ERP 导出，却常被迫先处理字段、SQL、模型和看板配置，才能回答一个简单问题。普通 AI 问答虽然更快，但容易脱离真实数据、静默猜测字段，且无法说明写入影响。

AIBI-C 要把“真实数据 -> 可信结果”压缩成渐进流程，同时保留专业用户需要的语义、关系、公式、视图和看板维护能力。

## Users

| User | Primary need | Default experience |
| --- | --- | --- |
| 运营、财务、供应链、电商、ERP 用户 | 从导出表快速得到趋势、排行、异常、对账或缺口 | 导入、证据摘要、自然语言单图 |
| 业务负责人 | 查看结果并确认可信度，不直接维护模型 | 图表、业务摘要、证据和明确缺口 |
| 数据实施或分析人员 | 修正语义、关系、指标和可复用资产 | 按需展开的高级维护区和 CLI |

## Core User Stories

1. 作为新用户，我可以导入文件或文件夹，并在写入前看到合并方式、行数、键质量和风险。
2. 作为业务用户，我可以直接描述一个图表；字段明确时得到一个草案，字段不明确时只回答一次可操作的澄清。
3. 作为结果使用者，我可以看到来源、指标口径、查询运行时和数据缺口，不需要先阅读技术回执。
4. 作为资产维护者，我可以保存视图、指标、公式、关系和看板，但每种对象只在一个主页面维护。
5. 作为工作区所有者，我可以预演、确认、拒绝或删除写入，并看到影响与完成回执。
6. 作为高级用户，我可以预演整套行业看板 Beta，但缺字段的单元必须被省略并说明原因。

## Primary Workflow

1. 创建或选择本地工作区。
2. 在 Sources 选择文件或文件夹，检查导入影响后确认。
3. 系统生成字段语义、质量和缺口证据；高级维护保持折叠。
4. 在 Dashboards 或全局 AI 描述一个图表或业务问题。
5. 系统使用当前工作区、字段证据和白名单查询形成答案或单图草案。
6. 用户在 Evidence 核对来源和口径。
7. 需要写入时，用户在唯一确认面审阅目标、影响和证据后确认或拒绝。

## Functional Requirements

### Workspace And Isolation

- 支持创建、选择和删除本地工作区。
- 表、字段、指标、关系、公式、保存视图、看板、证据和动作草案必须按工作区隔离。
- 页面跳转和全局 AI 必须保留当前工作区与所选对象上下文。
- 删除工作区必须先展示依赖对象和影响，再显式确认。

### Source And Import

- 稳定导入支持 CSV、XLSX 和 XLSM；旧 XLS 当前只支持证据画像读取，不承诺完整导入提交。
- 支持文件夹导入，并按同类表合并；合并前展示文件组、目标表、行数、键质量和冲突策略。
- 无数据时只显示导入所需控件，不展示图表、证据结论或高级建模工具。
- 导入提交是写入动作，必须经过一次明确确认并产生回执。

### Semantic, Metric And Relationship

- 字段语义包含角色、用途、置信度和手工覆盖。
- 自动指标和候选字段排除内部 `__*` 字段；自动清理不得删除手工资产。
- 关系推荐必须结合真实值重叠、基数和连接膨胀风险，不能只依赖字段同名。
- 指标、公式或关系缺少证据时，返回缺口或澄清，不生成确定结果。

### Query And Details

- 查询只接受白名单参数，不暴露任意 SQL。
- 支持明细、分组聚合、指标和关系查询，并返回运行时回执。
- 保存视图拥有唯一的创建、复制、删除和查询入口；其他页面通过上下文跳转使用视图。
- Details 查询面板在横屏、竖屏和正方形 PC 比例下保持可扫描，不挤压文字和操作。

### Dashboard

- 稳定默认是一次请求生成一个指标卡、柱状图、折线图、饼图、表格或文本洞察草案。
- 模糊请求最多进行一次必要澄清，并提供可点击的指标和维度候选。
- 图表草案展示目标看板、数据表、字段、聚合、口径、证据和写入影响。
- 筛选、关系分析、样式、组件维护和页面管理按需展开，不与单图创建竞争第一屏。
- 整套行业看板保持 Beta，必须先展示命中单元、省略单元、字段缺口和来源参考。

### Agent And Evidence

- 普通概览不默认选择销售、退款、渠道或任何特定行业字段。
- 只读回答不创建动作草案；写入意图只能生成待确认草案。
- Agent 必须披露当前使用确定性本地逻辑还是可选模型，并保持密钥在服务端边界内。
- Evidence 先展示业务摘要、可信度和缺口；原始回执、SQL 编译结果和诊断按需展开。

### Local Operations

- API 和 UI 默认只监听回环地址，拒绝远程通配绑定。
- 请求体有上限，错误响应可区分无效 JSON 和超限请求。
- 本地数据库支持校验和备份、恢复预演、确认恢复和恢复前安全副本。
- 备份不得包含 `.env`、源文件或凭据。

## Release Acceptance

- `npm run preflight` 通过，作为本地交付前总入口。
- `docs/product-acceptance-matrix.md` 中的稳定场景全部通过。
- 新工作区为空，生产 UI 不出现测试素材或默认业务结论。
- AI 单图可靠性覆盖空数据、模糊请求、显式柱图/折线图、未知字段和缺失维度。
- 浏览器验收覆盖空状态、真实导入闭环以及 Details 三种 PC 比例。
- CI 在 Windows runner 上通过构建、核心契约、生产安全和浏览器 smoke。
